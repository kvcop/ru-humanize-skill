# ru-humanize-skill

Скилл для русской вычитки агентских текстов: убрать канцелярит, лишние англицизмы, пустые связки и автогенерированную гладкость, не превращая текст в разговорный шум.

## Чтобы добавить себе

Попроси агента:

```text
Установи мне https://github.com/kvcop/ru-humanize-skill: прочитай README.md и skills/russian-humanize/SKILL.md, затем предложи, куда лучше добавить правила русского стиля — в мои глобальные или проектные AGENTS.md. Если для настройки стиля нужно посмотреть мои прошлые сессии, посты или документы, сначала предупреди меня и спроси разрешение. Сохрани язык и стиль моих текущих инструкций, адаптируй формулировки под мои сценарии письма, покажи diff и только после моего подтверждения внеси изменения.
```

## Что это делает

`russian-humanize` работает не как отдельная команда, а как фоновое правило для агента. Если агент пишет длинный русский текст, документацию, Telegram-пост, голосовой сценарий или повествовательную заметку, он сам выбирает тон под задачу и прогоняет текст через русскую самопроверку.

Главная идея простая: не “добавить человечности”, а убрать мусор. В тексте остаются смысл, ритм и живые русские связки; идентификаторы, команды и устойчивые технические термины остаются как есть.

## Инструкции для агента

Перед установкой не редактируй инструкции молча. Сначала определи, какой агент выполняет установку, и ищи правила в его собственной домашней конфигурации: для Codex это обычно `$CODEX_HOME` или `~/.codex`, для Claude Code — `~/.claude`, плюс проектные `AGENTS.md`, `CLAUDE.md` или другие локальные файлы. Не хардкодь чужие пути и не переноси настройки между агентами вслепую. Спроси, можно ли добавить туда правила русского стиля.

Сохрани язык уже существующих инструкций. Если файл написан по-английски, добавь английский блок. Если по-русски, добавь русский. Если у пользователя основной сценарий не документация, адаптируй формулировки: для Telegram-постов говори про Telegram-посты, для TTS — про голосовой текст, для заметок — про повествовательную прозу.

В качестве референса можно использовать такой блок:

```markdown
- Before sending a Russian user-facing answer, do a short Russian-language pass:
  reread the answer as ordinary Russian prose and replace accidental
  English/Russian hybrids with natural wording.
- Apply the same pass before writing or committing Russian user-facing
  documentation, Telegram posts, voice scripts, reports, or narrative notes.
- Use Russian for descriptive technical prose.
- Keep English only when it is a stable literal identifier or an accepted
  technical name: file paths, commands, code symbols, env variables, package
  names, protocols, product names, and established terms.
- Avoid hybrid phrases in Russian chat and Russian docs. Prefer fully Russian
  wording unless the literal identifier itself is the subject.
- Use the `russian-humanize` skill for long Russian prose and any text that
  will be spoken aloud.
```

Потом положи сам скилл туда, где этот агент хранит локальные skills. Обычно достаточно скопировать папку `skills/russian-humanize`; если место для skills неочевидно, спроси пользователя.

## Калибровка под голос пользователя

Если пользователь хочет сохранить свой стиль, не пытайся усреднить его до “правильного русского”. Сначала предупреди, какие сессии, посты или документы хочешь посмотреть, зачем это нужно и что именно будешь извлекать. Читай такие материалы только после согласия пользователя и не выноси приватные фрагменты в публичные артефакты.

Во время настройки собери короткий профиль голоса: любимые слова, темп, длину абзацев, уровень резкости, допустимый сленг, слова-маркеры, которые надо сохранять. “Дико”, “жрать”, “трещать”, “вот и весь gap” могут быть не ошибкой, а авторским почерком. Убирать стоит лишнюю англо-русскую кашу, канцелярит и пустые связки, а не характер.

Опционально предложи пользователю выбрать тон на живых примерах. Возьми пару тем из его существующих проектов или постов, перепиши каждую в 2-3 вариантах и спроси, какой ближе: документационный, Telegram-пост, повествовательный разбор, короткая заметка. После выбора адаптируй инструкции под этот стиль.

## Происхождение

Скилл сделан на основе идей и паттернов [`devswha/patina`](https://github.com/devswha/patina), но адаптирован под русскую прозу и агентские инструкции.

Первая версия появилась 01.04.2026, последнее обновление паттернов — 27.07.2026. Мы в основном проверяли сценарии с документацией, рабочими заметками и Telegram-сообщениями, поэтому какие-то жанры могут быть проработаны хуже.

Пул-реквесты с новыми русскими паттернами, примерами и аккуратными правками приветствуются.
